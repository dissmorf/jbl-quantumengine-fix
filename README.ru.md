# JBL QuantumENGINE: наушники определяются, но все настройки неактивны (серые) — решение

[English](README.md) | **Русский**

Неофициальное исправление для **JBL QuantumENGINE** под Windows. Помогает, когда беспроводные наушники JBL Quantum
(проверено на **Quantum 360P**) определяются и звук идёт, но **все настройки серые и не нажимаются**: нельзя поменять
эквалайзер, объёмный звук, самопрослушивание микрофона, автовыключение, а **обновление прошивки не предлагается**.

Как выглядит проблема:

- QuantumENGINE видит наушники, но все кнопки и ползунки серые.
- Звук и колёсико баланса игра/чат работают, только приложение не может управлять наушниками.
- Версия прошивки показывается как `0.0.0`, кнопки «Обновить прошивку» нет.
- Не помогают ни переустановка QuantumENGINE, ни переподключение донгла, ни перезагрузка.

## Коротко

Причина в **устаревшей прошивке донгла**. Старая прошивка на вопрос QuantumENGINE «подключены ли наушники?» всегда
отвечает «нет», и приложение блокирует всё, **включая обновление прошивки, которое бы это исправило**. Получается
замкнутый круг.

Эта утилита временно заставляет QuantumENGINE не верить этому неправильному ответу, чтобы можно было обновить прошивку.
После обновления вы возвращаете оригинальный файл, и всё работает в обычном, неизменённом приложении.

1. **Ставим патч** → настройки становятся активными.
2. **Обновляем прошивку** через QuantumENGINE.
3. **Возвращаем оригинальный файл** → готово.

> [!IMPORTANT]
> Это неофициальная утилита, она не связана с JBL или Harman. Вы используете её на свой риск.
> Файлов JBL в ней нет: она изменяет `QuantumServer.dll` из **вашей** установленной копии QuantumENGINE
> и сохраняет резервную копию оригинала.

## Что нужно

- Windows 10/11 (64-бит)
- **QuantumENGINE 2.8.6** (патчер проверяет версию и не станет патчить непроверенную)
- Наушники заряжены хотя бы на 50% (для обновления прошивки)
- Права администратора

## Пошаговая инструкция

### 1. Скачайте

1. Откройте страницу [**Releases**](../../releases/latest) и скачайте `QEWirelessFix-v*.zip`.
2. Щёлкните по архиву правой кнопкой → **Свойства**. Если внизу есть галочка **Разблокировать**, поставьте её и нажмите **ОК**.
3. Щёлкните по архиву правой кнопкой → **Извлечь всё…**. Появится папка с `install.cmd`, `restore.cmd` и `QEWirelessFix.exe`.

### 2. Установите патч

1. **Полностью закройте QuantumENGINE**, в том числе значок в трее возле часов (правой кнопкой → Выход).
2. Вставьте USB-донгл и **включите наушники**.
3. Щёлкните правой кнопкой по **`install.cmd`** → **Запуск от имени администратора**.
   - Если Windows покажет окно *«Система Windows защитила ваш компьютер»*, нажмите **Подробнее** → **Выполнить в любом случае**.
     Окно появляется потому, что у утилиты нет цифровой подписи. Её можно [собрать самостоятельно](#сборка-из-исходников).
4. Дождитесь зелёной надписи **`Patch installed.`** и нажмите любую клавишу.

### 3. Обновите прошивку

1. Откройте QuantumENGINE. Настройки должны стать активными.
2. Откройте страницу наушников и запустите **обновление прошивки**. Следуйте подсказкам на экране:
   QuantumENGINE может попросить подключить наушники USB-кабелем.
3. **Во время обновления не вынимайте донгл, не выключайте наушники и не закрывайте приложение.**
4. Когда обновление закончится, **проверьте обновления ещё раз**. У нас первый запуск обновил только наушники,
   а второй — донгл. Повторяйте, пока QuantumENGINE не скажет, что прошивка последняя.

Пример из наших логов: версии чипов `2.3.2 / 3.6.5` → `2.3.2 / 3.7.6` (первый запуск) → `3.7.5 / 3.7.6` (второй запуск).

### 4. Верните оригинальный файл

1. Закройте QuantumENGINE.
2. Щёлкните правой кнопкой по **`restore.cmd`** → **Запуск от имени администратора**.
3. Дождитесь надписи **`Original QuantumServer.dll restored.`**
4. Откройте QuantumENGINE и проверьте, что настройки по-прежнему активны, а эквалайзер меняет звук.

Готово! QuantumENGINE снова в исходном виде, его будущие обновления будут ставиться как обычно.

## Если что-то пошло не так

| Проблема | Что делать |
| --- | --- |
| `This QuantumServer.dll version was not tested` | У вас другая версия QuantumENGINE. Создайте issue. Или, на свой риск: откройте **Командную строку от имени администратора**, перейдите в распакованную папку (`cd /d "<папка>"`) и выполните `install.cmd -Force`. |
| После патча настройки всё равно серые | Убедитесь, что наушники включены, закройте и снова откройте QuantumENGINE. Если не помогло, создайте issue и приложите логи (см. ниже). |
| Обновление прошивки не предлагается | Подождите секунд 15 после запуска QuantumENGINE (он проверяет сервер JBL). Проверьте, что есть интернет. |
| После `restore.cmd` настройки снова серые | Скорее всего, прошивка всё ещё старая: поставьте патч снова и повторите шаг 3. Можно и оставить патч (обновление QuantumENGINE его перезапишет). |
| Эквалайзер переключается, но разницы не слышно | Если наушники подключены USB-кабелем, отключите кабель, чтобы звук шёл через донгл. |
| `Backup ... not found` | Оригинал уже восстановлен или резервная копия удалена. Переустановка QuantumENGINE всегда возвращает оригинальный файл. |

### Как собрать логи для issue

Служба QuantumENGINE пишет логи в `C:\Windows\SystemTemp\QuantumENGINE` (в старых версиях Windows 10:
`C:\Windows\Temp\QuantumENGINE`), читать их может только администратор.
Чтобы скопировать их в `Документы\qe-logs`, выполните в PowerShell **от имени администратора**:

```powershell
$dst = "$env:USERPROFILE\Documents\qe-logs"; New-Item -ItemType Directory -Force $dst | Out-Null; foreach ($p in 'C:\Windows\SystemTemp\QuantumENGINE','C:\Windows\Temp\QuantumENGINE') { if (Test-Path $p) { Copy-Item "$p\*" $dst -Force } }
```

Также приложите `%LOCALAPPDATA%\Temp\QuantumENGINE\QuantumClient.log`.
В логах есть модель компьютера и идентификатор устройства. Просмотрите их перед публикацией.

## Каких наушников это может касаться

Исправленный код в QuantumENGINE общий для семейств **Quantum 350, 360 / 360P / 360X / 360XB, 600, 610, 800, 810,
910 / 910P / 910X, Quantum TWS**.

**Проверено только на Quantum 360P.** Если на другой модели сработало (или нет), напишите об этом в issue.

## Как это работает (технические подробности)

QuantumENGINE состоит из двух частей: окна (`QuantumEngine.exe`) и фоновой службы Windows (`QuantumServer.exe`, служба
`QuantumService`), которая общается с донглом по USB HID.

1. Для наушников серии Quantum 360 окно включает настройки, только если `WirelessConnected && Ready`
   (`Q360Series/ProductUI.cs`, метод `CheckDeviceEnable`).
2. `WirelessConnected` приходит от службы. При открытии HID-устройства она запрашивает у донгла feature report
   **`0x68`** («подключены ли наушники по радио?»), а дальше ждёт input report **`0x09`** (связь изменилась).
3. Со старой прошивкой донгл **всегда** отвечает `0x68 → 0x00` и никогда не присылает `0x09`, даже когда наушники
   подключены, звук идёт, а колёсико баланса присылает `0x10xx` через тот же HID-канал:

   ```text
   [HIDV1] [Get    ] 0x6800      <- служба перезапущена при подключённых наушниках
   [HIDV1] [Input  ] 0x1010      <- колёсико баланса при этом работает через донгл
   ```

4. Из-за этого служба не выполняет свою логику «наушники подключены» (чтение версии прошивки, эквалайзера и т.д.),
   приложение показывает прошивку `0.0.0`, а программе обновления не с чем сравнивать, и она ничего не предлагает.

**Патч** добавляет один метод в класс `QEService.Feature.MiscFeature+WirelessConnection+HIDV1` в `QuantumServer.dll`:

```csharp
protected override void OnHIDPropertyChanged(in byte value)
{
    byte connected = 1;
    base.OnHIDPropertyChanged(in connected);   // всегда сообщать «подключены»
}
```

Больше ничего не меняется. С патчем служба читает настоящую версию прошивки (`2.3.2 / 3.6.5`), QuantumENGINE находит
более новую на сервере JBL (`3.7.5 / 3.7.6`) и может её установить. После обновления донгл сам сообщает о подключении
(`[Input] 0x0901`), и патч больше не нужен.

### Командная строка патчера

```text
QEWirelessFix check <QuantumServer.dll>
QEWirelessFix patch <QuantumServer.dll> <output.dll> [--force]
```

Коды выхода: `0` успех, `1` ошибка аргументов или файла, `2` уже пропатчен, `3` непроверенная версия (используйте
`--force`), `4` это не тот файл.

`install.ps1` и `restore.ps1` принимают `-InstallDir <папка>`, если QuantumENGINE установлен не в
`C:\Program Files\JBL\QuantumENGINE`.

## Сборка из исходников

Нужен [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0).

```powershell
dotnet publish patcher -c Release -o dist
Copy-Item scripts\* dist
```

В папке `dist` будут те же файлы, что и в архиве релиза. Релизы собирает GitHub Actions из этих исходников
(см. `.github/workflows/release.yml`).
